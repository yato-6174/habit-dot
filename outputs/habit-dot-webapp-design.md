# 習慣ドット Webアプリ 設計書（アカウントなし・PWA版）

作成日: 2026-08-24  
対象: アプリ開発に詳しくない方にも共有できる、最初の設計メモ  
方針: アカウントを作らず、iPhoneのブラウザから使えるWebアプリとして公開する

## 1. このアプリでできること

「続けたいこと」を1つ以上登録し、できた日にボタンを0.8秒長押しすると、画面上のドットが1つ増えるWebアプリです。

たとえば「読書」を続けたい場合、読書できた日に「できた」を押します。読書用のドットが1つ増え、積み上げがひと目でわかります。ドットが増えていくこと自体を、小さな達成感にします。

### 初期版のゴール

- 迷わず習慣を登録できる
- 気持ちよい長押し操作で今日の達成を記録できる
- これまでの積み上げをドットで楽しく見られる
- スマートフォンでもパソコンでも使いやすい

## 2. 想定する利用の流れ

1. アプリのURLを開く（ログインは不要）
2. 「読書」「散歩」など、続けたいことを登録する
3. できた日に、その習慣の「今日できた」ボタンを0.8秒長押しする
4. ドットが1つ増え、連続記録や合計回数も更新される
5. 後日、ドットの並びを見て、自分の積み上げを振り返る

誤って押した場合は、当日分のみ取り消せるようにします。

## 3. 画面の設計

### A. ホーム画面（毎日使う画面）

最も大切な画面です。登録した習慣をカード形式で並べます。

各カードに表示するもの:

- 習慣名（例: 読書）
- 今日の状態（未記録 / 達成済み）
- 大きな「今日できた」長押しボタン
- 今月のドット一覧
- 連続日数と合計回数

イメージ:

```text
┌────────────────────────────┐
│ 読書              12日連続 │
│ ● ● ● ● ● ● ● ● ○ ○ ○ ○   │
│                            │
│   ◎ 今日できた（長押し）   │
└────────────────────────────┘
```

- `●` は達成した日、`○` はまだ記録していない日です。
- 「今日できた」は、ボタンを0.8秒間長押しして記録します。押している間は、ボタンの縁の円形ゲージが0%から100%まで満ちます。
- 指を途中で離したり、ボタンの外へ動かしたりした場合は、記録せずにゲージを戻します。
- 完了時は、ドットが増える小さなアニメーションと軽い振動（対応端末のみ）で達成感を伝えます。
- 達成済みになると、ボタンは「今日の記録を取り消す」に変わります。

### 長押し操作の決め方

長押しの時間は **0.8秒** とします。誤って触れただけで記録されることを防ぎながら、毎日使っても待たされにくい長さです。

- 0.0〜0.8秒: ゲージが滑らかに進む
- 途中で指を離す: 記録せず、ゲージを戻す
- 0.8秒到達: 達成として保存し、ドットを1つ追加する
- 触覚フィードバック: 0.4秒付近にごく軽く、完了時に明確に1回（利用できる端末のみ）

操作を初めて見る人にもわかるよう、ボタンの下に「0.8秒長押しで達成」と小さく表示します。慣れた人のために、説明は何度も強調しません。

### B. 習慣を追加する画面

入力は少なくします。

- 習慣の名前（必須、例: 10分散歩）
- ドットの色（選択式）
- アイコン（任意、例: 本・靴・水滴）
- 目標の頻度（任意: 毎日 / 週に○回）

初期版では、習慣名だけでも登録できます。

### C. 習慣の詳細画面

ひとつの習慣を深く振り返る画面です。

- 月ごとのドットカレンダー
- 今月の達成回数
- 最長連続日数
- これまでの総達成回数
- 習慣の編集・削除

### D. データとバックアップ画面

- 最終バックアップ日時
- バックアップファイルを作成する
- バックアップファイルから復元する
- すべてのデータを削除する
- 「この端末・このブラウザに保存されています」という注意書き

## 4. 最初のリリースに入れる機能（MVP）

MVPとは「まず使い始められる最小限の完成版」です。

| 機能 | 内容 | 初期版に入れる理由 |
| --- | --- | --- |
| 習慣の登録 | 名前・色・アイコンを設定する | 自分向けの一覧を作れる |
| 今日の達成記録 | 0.8秒の長押しでドットを増やす | 誤操作を防ぎつつ、達成感を作る中心機能 |
| 記録の取り消し | 間違えた当日分を戻す | 気軽に使える |
| ドット表示 | 月ごとの積み上げを見せる | 続ける楽しさになる |
| 連続日数・総回数 | 数字で成果を補助表示する | 成長を実感できる |
| 習慣の編集・削除 | 名前や色を変え、不要なら消す | 長く使いやすい |
| バックアップ・復元 | データをファイルに保存し、戻せる | 機種変更やブラウザ消去に備える |

## 5. 後から追加できる機能

初期版が使われてから、必要性を見て追加します。

- 通知・リマインダー（例: 毎晩20時に通知。Web版では端末やブラウザによって制限あり）
- 友人との共有、応援機能
- 写真やメモの記録
- 週・月ごとの振り返りレポート
- 達成時の小さなアニメーションやバッジ
- ホーム画面からすぐ開けるショートカット表示の改善
- データをCSV形式でダウンロード

## 6. デザイン方針

### 目指す印象

明るく、静かに背中を押してくれるデザインにします。ゲームのように派手すぎず、記録する行為が負担にならないことを大切にします。

### 使いやすさのルール

- ホーム画面を開いたら、すぐ記録できる
- 重要なボタンは親指で押しやすい大きさにする
- 色だけに意味を持たせず、文字やアイコンでも状態を伝える
- 小さな文字や難しい言葉を避ける
- ダークモードにも対応できる設計にする

## 7. データの考え方

利用者の情報は、次のように保存します。

| 保存するもの | 例 |
| --- | --- |
| 習慣 | 読書、散歩、水を飲む |
| 習慣の見た目 | 色、アイコン |
| 達成記録 | 「2026年8月24日に読書を達成」 |

1日に同じ習慣を何度も押しても、初期版ではドットは最大1つです。これにより「今日できたか」をシンプルに扱えます。

## 8. 技術の設計（開発者向けの補足）

利用者にはアカウント作成やアプリのインストールを求めず、ブラウザで開けるWebアプリとして作成します。Safariの共有メニューから「ホーム画面に追加」を選ぶと、アイコンからアプリのように起動できます（PWA）。

- 画面: React / Next.js
- 端末内の保存: IndexedDB（ブラウザ内の専用データ保存領域）
- バックアップ: JSONファイルの書き出し・読み込み
- 公開先: Vercel などのWebホスティング
- 独自ドメイン: 既に所有しているドメインを公開先に接続
- 通信: HTTPS（鍵マークが付く安全な接続）を必須にする

この構成は、小さく始めやすく、個人情報を預からないため運用負担も小さい構成です。

### 保存とバックアップの詳しい方針

通常の記録は、使っているブラウザ内のIndexedDBに保存します。サーバーには習慣名や達成記録を送信しません。

- 記録した直後に自動保存する
- 「バックアップを作成」ボタンで、全データをJSONファイルとして端末にダウンロードする
- 「バックアップから復元」で、そのJSONファイルを読み込み、機種変更時などに記録を移せるようにする
- バックアップの作成を、月に1回程度アプリ内でやさしく案内する
- 復元前には、現在のデータを自動バックアップしてから上書きする

JSONはアプリ用の完全バックアップです。加えて、必要であれば達成記録だけをCSV形式で出力し、Excelなどで見られるようにします。

### この方式で知っておくこと

- 同じスマホでも、SafariとChromeは別々の保存場所です
- ブラウザのデータを消去すると、アプリの記録も消える可能性があります
- 別のスマホやPCへは自動同期されません。バックアップファイルを使って移します
- iOS標準のホーム画面ウィジェットは、Webアプリだけでは作れません

## 9. 既存ドメインの利用方法

以前作成したドメインを、このアプリのURLとして使います。例として、`https://your-domain.example` のような形で公開します。

公開時には、ドメインを管理しているサービスで以下を設定します。

1. Webアプリの公開先（例: Vercel）にドメインを登録する
2. ドメイン管理画面で、案内されたDNS設定を追加する
3. 接続確認後、HTTPSを有効にする

実際に進める段階で必要なのは、ドメイン名と、そのドメインを管理しているサービスへの操作権限です。現時点ではドメイン名がこのスレッドにないため、設計上は「既存ドメインを接続する」として進めます。

## 10. 安全性とプライバシー

- アカウント、メールアドレス、パスワードは扱わない
- 日々の習慣記録は原則として利用者のブラウザ内にのみ保存する
- サーバー側に利用者の習慣データベースを持たない
- 利用者がバックアップファイルを保管する場所は、本人が選べる
- データを消去する操作には確認画面を出す

## 11. 開発の進め方

1. この設計書を確認し、必要な調整を決める
2. 画面の見た目を確認できるデザイン案を作る
3. 初期版を実装する
4. テスト用URLでiPhoneのSafariを中心に使いやすさを確認する
5. バックアップ・復元が確実に動くことをテストする
6. 既存ドメインを接続して公開する
7. 実際の利用をもとに、通知や振り返り機能を追加する

## 12. 次に決めるとよいこと

- アプリの名前
- 使いたい既存ドメイン名
- バックアップをどこに保管するか（iCloud Drive、Google Drive、端末内など）
- ドットの雰囲気（シンプル / かわいい / 落ち着いた）
- iPhoneのSafariを主な利用環境にするか
